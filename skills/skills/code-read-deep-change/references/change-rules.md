# 变更阅读规则（change-rules）

> 供 `code-read-deep-change` 的阶段 1~6 使用。核心：读懂**一次变更（diff / PR / commit 范围）改了什么、为什么、影响半径多大**——是**理解**，不是质量评判（质量评判是 `code-review-deep-zh`）。

---

## 一、变更来源获取（阶段 1）
- 支持来源：工作区改动（`git diff`）、暂存区（`git diff --cached`）、提交范围（`git diff A..B`）、单个 commit（`git show <sha>`）、PR（`gh pr diff <n>`）、或用户直接给的 `.diff`/`.patch` 文本。
- 用 git 命令**只读**取 diff：`git diff`、`git diff --stat`、`git log --oneline A..B`、`git show`。
- **闸门**：确认意图是"**读一次变更**"。若用户要读**现有代码**（非变更）→ 改道容器 skill（function/file/module/project）；若要**质量评判/找 bug 打分/能不能合** → `code-review-deep-zh`。

## 二、变更范围与分类（阶段 2）
- 用 `--stat` 列改动文件，每个文件标 新增/删除/修改 + 行数。
- 落到**符号级**：哪些类/方法/函数/字段被增删改、**签名/返回值/异常是否变**。

## 三、改了什么 + 意图推断（阶段 3）
- 逐处描述**实质改动**（不是逐行念 diff，而是"这处把 X 改成 Y，效果是 Z"）。
- **意图**：结合 commit message / PR 描述 / 周边上下文 / git 历史（用 `reading-lenses.md` 的"git 历史"视角）推断"为什么这么改"。

## 四、影响半径（阶段 4）→ 影响半径图
- 对每个**被改的对外符号**（公共方法/导出函数/签名变了的/返回语义变了的/被删除的），全库反查**调用方/消费方**。
- 重点盯：签名/参数/返回值/异常/契约变化的下游**是否需同步改**；被删除的符号**是否仍被引用**；新增依赖**是否已装配**。
- 跨模块/跨文件的波及都要标。
- 深挖某调用方 → 容器 skill；想沿某条受影响线索追到底 → `code-read-deep-trace`。

## 五、关联测试（阶段 5）
- 被改代码有无对应测试？测试是否覆盖改动的**新行为/边界**？哪些测试**需更新**（用 `reading-lenses.md` 的"测试即规格"视角）。

## 六、风险面（阶段 6）—— 本 skill 特有视角
- **行为变化点**、**边界/兼容性影响**、**可能遗漏的受影响路径**、**未同步更新的调用方/测试/文档**。
- 这是"理解层面的风险提示"，不是质量评分。

## 七、与 `code-review-deep-zh` 的边界
- 本 skill 答"**改了什么 / 为什么 / 波及谁 / 有哪些风险点**"（理解）。
- **不**做"这改得好不好 / 有没有安全性能问题 / 该不该合"（评判）——那是 `code-review-deep-zh`。

## 八、取舍原则
- **只读不改**：不改 diff、不改代码、不提交。
- diff 大时按"**对外/高风险符号优先**"反查影响半径，其余标"（未逐一反查）"。
- 多语言/多框架：按生态识别被改符号与其调用点。
