# 止血手段与生产安全

止血的目标是**尽快缩小影响**，不是"把系统改回原来的样子"。选手段的唯一标准是：在能达成止血的前提下，**代价最小、可逆性最好、副作用最清楚**。

## 手段清单与代价对照

可逆性从高到低排列；越靠下越要谨慎，越靠下越接近不可逆。

| 手段 | 代价 / 副作用 | 可逆性 | 授权要求 | 执行前后必须记录 |
|---|---|---|---|---|
| 降级开关 | 部分功能不可用或走简化逻辑，用户可感知 | 高，关掉即恢复 | 值班负责人按预案可直接执行 | 开关名与当前值、影响的功能、恢复后误差 |
| 限流 / 熔断 | 正常流量也被拒，可能丢请求 | 高，改回阈值即恢复 | 值班负责人按预案可直接执行 | 阈值、被拒比例、是否有请求被丢弃 |
| 切流量 / 摘节点 | 备用链路容量与数据一致性风险 | 中高，切回即恢复 | 值班负责人可执行；跨机房/跨云切换需升级 | 切换前后的流量分布、切换后指标、数据是否双写 |
| 回滚版本 | 回滚会丢掉新版本的数据结构或功能，可能**不可逆地影响已写入的数据** | 中，可再发新版但数据难回退 | **需逐项授权**，由发布负责人或值班负责人批准 | 回滚的目标版本、当前版本、回滚前后指标、是否涉及数据库变更 |
| 扩容 | 成本上升；若瓶颈不在容量则完全无效 | 高，但缩容要另做 | 需明确授权（尤其生产集群） | 扩容规格与数量、扩容后指标是否真的改善 |
| 重启 | 掩盖现象、丢失现场（内存、连接状态、堆栈）、可能触发集中重连风暴 | 高（动作本身可逆），但**证据不可逆** | **需逐项授权** | 重启前先抓现场（日志、线程/堆栈、内存快照）、重启范围、重启后是否复发 |
| 临时封禁 / 限用户 | 直接伤害用户，可能误伤正常用户，且有合规与舆论风险 | 中，解封即恢复 | **需逐项授权**，涉及用户影响时需业务方同意 | 封禁规则与命中量、误伤评估、解封条件与时限 |
| 数据修复（改/删数据） | **风险最高**，见下节 | 取决于是否可回滚 | **单独授权 + 双人确认** | 备份位置、影响行数预估、执行 SQL 或脚本、执行后校验结果 |

通用规则：

- 每个手段执行前写清**预期效果与副作用**，执行后立即验证效果；没有副作用的止血手段几乎不存在。
- 一次只改一个变量。同时回滚版本又清缓存又扩缩容，事后无法知道哪个动作起了作用。
- 记录"执行前"的状态：只记录执行后的指标，就无法证明动作有效。

## 数据修复为什么风险最高

代码可以回滚，**数据不能**。数据修复直接改变业务事实，且往往是"为了让现象消失"而做，最容易在范围未确认时扩大伤害。

数据修复的前置条件，缺一项就不做：

1. **备份。** 被修改的数据在动手前有可恢复的备份，并确认备份可读、位置记入时间线。
2. **影响行数预估。** 先用 `SELECT` 统计将要命中的行数与样本；行数远超预期就停下重新评估范围。
3. **可回滚方案。** 明确怎么撤销这次修复：反向脚本、备份还原，或至少一条逐条可确认的记录。只会往前修不算方案。
4. **双人确认。** 执行者之外的第二人复核范围、语句与备份，确认后才执行。
5. **单独授权。** 数据修复**单独列出、单独申请授权**，不与止血动作打包；"先止血顺便把脏数据清了"是最危险的说法。
6. **执行后校验。** 修复后用查询或对账验证结果，把修正前后的数量记入时间线；未验证就写"尚未验证"。

## 绝不能作为止血手段的操作

- **直接清库、TRUNCATE、DROP。** 数据消失后没有任何现场可以复盘，也无法证明恢复。
- **跳过备份改数据。** "时间紧，先改了再说"是事故升级的标准起点。
- **在范围未确认时批量改数据。** 命中范围没算清就执行 UPDATE/DELETE。
- **清空缓存当作结论。** 清缓存可以让现象消失，但它既不是根因，也常把证据一起清掉；要做就必须先记录清掉了什么、以及清之前的现象。
- **无记录地重启数据库或存储。** 重启会清掉内存现场，且可能触发长时间恢复。
- **为了"看起来恢复了"而修改监控、阈值或告警规则。** 这属于篡改证据。
- **在没有授权时替用户决定回滚或封禁用户。** 破坏性操作逐项授权，用户一句"你看着办"不构成授权。
- **重写或美化时间线。** 时间线是复盘的基础事实，只增不改。

## 现场与后续的分界

止血动作成功只说明**影响被压住了**。要让根因定位接手：

- 把"止血前后系统状态的差异"整理清楚：哪些配置/版本/流量变了，指标怎么变的。
- 保留现场：日志片段、traceId、堆栈、慢查询、重启前的内存与线程信息。
- 明确列出**遗留未验证项**：哪些动作的效果没确认、哪些数据没核对、哪些观察没做。
