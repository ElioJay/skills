# 30-系统设计

**阶段**：设计。回答"怎么做"。表中的概要设计与详细设计拉平为 9 个活动：`31` 到 `34` 是概要设计，`35` 到 `37` 是详细设计，`38` 是横切的非功能设计，`39` 是出口。

| 目录 | 表中活动 | 典型产出 |
|---|---|---|
| `31-现状分析` | 表外补充：既有系统解读 | 模块架构总览、数据模型、核心流程、技术债 |
| `32-架构设计` | 概要设计：架构、技术选型 | 技术方案、部署与集成架构、选型决策 |
| `33-模块划分` | 概要设计：模块划分 | 模块边界、依赖关系、分层约定 |
| `34-接口设计` | 概要设计：接口契约 | 接口文档、接口简表、OpenAPI 导出 |
| `35-数据设计` | 详细设计：库表 | 库表设计源、数据字典、新旧对照、差异脚本 |
| `36-类与接口` | 详细设计：类与接口 | 类图、时序图、状态图、算法说明 |
| `37-页面设计` | 详细设计：页面 | 原型、页面流、交互说明 |
| `38-性能安全` | 表外补充：非功能设计 | 性能、安全、事务、缓存、日志监控的设计约定 |
| `39-设计评审` | 表外补充：设计评审 | 评审记录、追溯矩阵 |

**出口条件**：设计评审通过；库表、接口、页面与需求可追溯。

**易混淆**：`31-现状分析` 写的是"现在是什么样"，`32-架构设计` 写的是"要改成什么样"。同一模块两者都有很正常，先解读再设计。
