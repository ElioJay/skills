# .docs 目录结构：按软件研发生命周期组织

项目文档库的标准布局。**一级目录是生命周期的 8 个阶段，二级目录是每个阶段的核心活动**，两者对应下面的阶段表；另加两组 AI 目录：`00-AI开发` 管用 AI 做软件，`90-AI系统` 管做的软件里有 AI。

配套文档 [`软件研发生命周期.md`](./软件研发生命周期.md) 解释每个阶段、贯穿活动和两组 AI 内容是什么、产出什么、何时算完成。

---

## 命名规则

- **两位数字前缀 + 4 个字**，一级、二级都是，列表天然对齐。`00-AI开发`、`90-AI系统` 含拉丁字母 AI，是仅有的两处例外。
- 十位数是组，`N0` 是组目录本身；个位数是活动，`N1` 到 `N9`。`10` 到 `80` 是八个阶段，`00` 是 AI 辅助研发，`90` 是 AI 系统研发。
- 三级目录不编号，按各活动自己的约定（需求编号、日期、模块名）组织。
- 每个目录都有一个 `README.md` 说明它对应表中哪个活动、放什么、怎么命名。

## 按需拆目录

- 二级目录是标准分类，**空着也保留 README**，它的存在就是在告诉你"这类东西放这里"。
- 二级之下不预建目录。同一活动内的不同类别先用文件名前缀区分，某一类攒到 5 个以上再拆成子目录。
- 不要为"将来可能有"的文档新建目录；先放进最接近的活动目录，README 里补一行说明。

## 与阶段表的对应

| 阶段 | 表中核心活动 | 目录 |
|---|---|---|
| 1 立项与可行性 | 明确业务目标、范围和收益，评估技术与资源可行性，定预算和里程碑 | `10-立项调研` 下 `11` `12` `13` |
| 2 需求 | 需求调研与获取、分析建模、编写规格、需求评审、建立基线，之后走变更管理 | `20-需求工程` 下 `21` 到 `26` |
| 3 设计 | 概要设计：架构、技术选型、模块划分、接口契约；详细设计：库表、类与接口、页面 | `30-系统设计` 下 `32` 到 `37`；`31` `38` `39` 为表外补充 |
| 4 开发 | 编码、单元测试、代码评审、持续集成、静态检查 | `40-开发实现` 下 `41` 到 `45` |
| 5 测试 | 测试计划与用例、集成测试、系统测试、性能与安全测试、回归、用户验收 | `50-测试验证` 下 `51` 到 `56` |
| 6 发布与部署 | 版本冻结、发布评审、打包、升级脚本、灰度或全量部署、回滚预案 | `60-发布部署` 下 `61` 到 `66` |
| 7 运维与维护 | 监控告警、线上问题处理、缺陷修复、性能优化、小版本迭代 | `70-运行维护` 下 `71` 到 `75` |
| 8 退役 | 数据迁移归档、系统下线、资料归档 | `80-系统下线` 下 `81` `82` `83` |
| 表外 | AI 辅助研发 | `00-AI开发` 下 `01` 到 `04` |
| 表外 | AI 系统研发 | `90-AI系统` 下 `91` 到 `97` |

活动名压成 4 字时的取舍：`编码` 写成 `代码编写`，`打包` 写成 `构建打包`，`回归` 写成 `回归测试`，`测试计划与用例` 写成 `测试设计`，`性能与安全测试` 写成 `性能安全`，`灰度或全量部署` 写成 `部署上线`，`线上问题处理` 写成 `线上问题`，`小版本迭代` 写成 `版本迭代`，`数据迁移归档` 写成 `迁移归档`；设计阶段 `技术选型` 并入 `架构设计`，`非功能设计` 写成 `性能安全`。每个目录的 README 都写着原文。

## 一份文档该放哪

先定组：提示词、技能、MCP、AI 使用约定、工作流说明进 `00-AI开发`；模型、训练数据、模型评估、AI 影响评估进 `90-AI系统`；其余按它回答的是"该不该做、做什么、怎么做、做出来、做对了吗、怎么上、上了之后、怎么下"里的哪一个定阶段。再进组目录读 README 的活动表，按"表中活动"那一列对号入座。

## 落地到一个项目

1. **备份**。`.docs` 通常不在 git 里，先整个打包一份再动。
2. **复制骨架**。把本目录整套复制到项目根 `.docs/`，包括空目录的 README。不做 AI 功能的项目可以整组删掉 `90-AI系统`。
3. **搬文件**。按项目自己的映射表把现有文档搬进对应活动目录。
4. **同步硬编码路径**。skill、spec、归档任务、文档互链里写死的 `.docs/xx-` 路径逐个改；skill 若有单源同步机制，改源再重新生成。
5. **自查残留**：

   ```bash
   grep -rn "<旧目录名>" --include="*.md" --include="*.py" --include="*.sh" --include="*.json" --include="*.jsonl" --include="*.yaml" . | grep -v /target/
   ```

6. **写变更记录**。在项目 `.docs/README.md` 末尾记一条：日期、旧名到新名、引用已同步。
